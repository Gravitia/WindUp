# 에디터 작업 마무리 · 검증

## 순서를 지킨다

1. **읽고 나서 쓴다.** 그래프, 테이블, 위젯 트리, 나이아가라 스택은 현재 구조를 먼저 조회한다. 구조를 모른 채 쓰면 조용히 깨진다.
2. **프로퍼티 이름을 추측하지 않는다.** `ObjectTools.list_properties`로 확인하고 쓴다. 틀린 이름의 `set_properties`는 에러 없이 실패한다.
3. 블루프린트를 고쳤으면 `BlueprintTools.compile_blueprint`로 컴파일한다.
4. `AssetTools.save_assets`로 저장한다. 저장하지 않으면 에디터를 닫을 때 사라진다.
5. 수정 결과를 **다시 읽어 확인한다.** 그래프는 `read_graph_dsl`이 빠르다.

## 보고

- 컴파일이나 테스트가 실패하면 실패했다고 그대로 말하고 출력을 보여준다. 통과한 것처럼 요약하지 않는다.
- 저장이나 컴파일을 건너뛰었으면 건너뛰었다고 말한다.
- 확인까지 끝났으면 군더더기 없이 됐다고 말한다.

## 추측보다 로그

"안 된다"는 보고를 받으면 코드를 고치기 전에 `LogsToolset`으로 출력 로그를 먼저 읽는다. 관련 로그가 안 보이면 해당 카테고리 verbosity를 올리고 재현한다.

UI 레이아웃이나 이펙트처럼 눈으로 봐야 하는 문제는 뷰포트 스크린샷으로 확인한다. 텍스트만으로 추론하지 않는다.

## PIE

런타임 상태 조회는 PIE가 켜져 있어야 의미가 있다. 조사가 끝나면 정지한다. 켜둔 채 두지 않는다.

## 에디터 상태를 함부로 바꾸지 않는다

레벨 전환, 액터 삭제, 플러그인 토글, 프로젝트 설정 변경은 사용자의 작업 중인 에디터에 즉시 영향을 준다. 실행 전에 무엇이 바뀌는지 알린다.
