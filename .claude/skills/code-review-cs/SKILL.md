# 다중 에이전트 코드 리뷰

탐색과 반박을 분리한다. 한 모델이 찾고 스스로 판정하면 자기 발견을 과대평가한다. **찾는 쪽과 깎는 쪽을 다른 에이전트로 나누는 것이 이 스킬의 전부다.**

## 전제

- 대상은 **텍스트 소스**다: `Source/` 아래 `.h` / `.cpp` / `.cs`, `Config/` 아래 `.ini`.
- **블루프린트·레벨·머티리얼 등 `.uasset`은 이 스킬의 대상이 아니다.** 요청에 포함되면 `unreal-blueprint` 등 MCP 스킬로 별도 처리한다고 알리고, C++ 리뷰만 진행한다.
- 리뷰는 **읽기 전용이다.** 탐색·반박 에이전트는 파일을 수정하지 않는다. 수정은 보고 후 사용자가 지시할 때 메인 에이전트가 한다.

## 0단계 — 범위 확정

인자가 없으면 기본값은 **현재 브랜치의 미커밋 변경 + `main` 대비 커밋**이다.

```bash
git diff main...HEAD --stat; git status --short
```

인자로 경로, 커밋 범위, 파일 목록이 주어지면 그것을 쓴다.

범위를 확정한 뒤 **변경 파일 목록과 총 라인 수를 사용자에게 먼저 보여준다.** 변경이 3,000줄을 넘으면 에이전트 6개를 띄우기 전에 범위를 좁힐지 묻는다.

## 1단계 — 탐색 에이전트 3개 (병렬)

`Agent` 툴을 **한 응답 안에서 3번 호출**한다. 그래야 병렬로 돈다.

- `subagent_type`: `general-purpose`
- `model`: `opus`
- `run_in_background`: 기본값(백그라운드) 유지

셋 다 **같은 탐지 축 전체를 본다.** 다른 것은 접근 경로뿐이다. 같은 결함을 여럿이 찾으면 확신도가 올라가고, 혼자 찾은 것은 반박 단계에서 걸러진다.

| | 접근 경로 |
|---|---|
| 탐색 A | diff 중심. 바뀐 줄과 그 주변만 정밀하게 본다. |
| 탐색 B | 런타임 흐름 중심. 바뀐 함수의 호출자·피호출자를 따라가며 실제 실행 경로를 재구성한다. |
| 탐색 C | 정적 패턴 중심. 변경 파일 전체를 읽고 위험 패턴을 grep으로 훑는다. 줄바꿈·인코딩은 C가 반드시 확인한다. |

### 탐지 축

프롬프트에 이 표를 그대로 넣는다. ID는 이후 단계에서 계속 쓴다.

| ID | 축 | 구체적으로 볼 것 |
|---|---|---|
| `CRASH` | 크래시 | null/dangling 역참조, `Cast<>` 결과 미검사, 배열·인덱스 범위, `UPROPERTY()` 없는 `UObject*` 멤버(GC에 수거됨), `GetWorld()`/`GetOwner()` 무검사, 소멸·`EndPlay` 이후 접근 |
| `LOOP` | 무한루프·행 | `while` 종료 조건, 재귀 깊이, `Tick`에서의 O(n²), 이벤트 상호 재진입, 조건이 영원히 참일 수 있는 대기 |
| `PERF` | 성능 | 매 프레임 힙 할당·`FString` 조립·`FindObject`/`GetAllActorsOfClass`, `TArray` 값 복사, 불필요한 `Cast`, 로그 스팸, 꺼도 되는 `Tick` |
| `NET` | 멀티플레이 | 권한(`HasAuthority`) 체크 없는 상태 변경, 리플리케이션 누락, 클라 전용 연출(사운드·VFX·UI)과 서버 소유 상태의 혼재, RPC 방향 오류. **중도 접속은 없다(규칙 04) — 재동기화 경로 부재를 결함으로 올리지 마라.** 단 클라이언트별 초기화 순서 의존은 여전히 결함이다. |
| `LOGIC` | 정확성 | 경계 조건, 부호·형변환, 조기 반환 누락, 상태 머신 전이 누락 |
| `REUSE` | 재사용성 | 중복 코드, 하드코딩 상수, 이미 있는 유틸 재구현, 과도한 결합, 헤더 과다 include |
| `TEXT` | 줄바꿈·인코딩 | CRLF/LF 혼재, 한글 주석 파일의 UTF-8 BOM 누락(MSVC에서 깨짐), 탭/스페이스 혼용, 파일 끝 개행 누락, trailing whitespace |
| `CONV` | 프로젝트 규칙 | `CSEditable\|<시스템>` 카테고리(규칙 06), 폴더 배치(규칙 03), 생성 디렉터리 수정 여부(규칙 02) |

`TEXT` 축은 이렇게 확인한다.

```bash
file Source/ChronoSpace/**/*.cpp | grep -v "CRLF" 
grep -rlIP '\r\n' Source/ChronoSpace | head -50
```

### 탐색 에이전트 프롬프트 템플릿

```
너는 Unreal Engine 5.8 C++ 코드 리뷰어다. 리슨 서버 기반 멀티플레이 프로젝트다.

[읽기 전용] 파일을 절대 수정하지 마라. Edit/Write를 쓰지 마라.

## 리뷰 대상
<파일 목록 / diff 범위>

## 접근 경로
<A/B/C 중 하나의 설명>

## 프로젝트 규칙 (위반은 CONV로 보고)
저장소 루트 기준 `.claude/rules/` 아래 파일 전부를 먼저 읽어라. 특히 `04-multiplayer.md`(권한·리플리케이션, **중도 접속 클라이언트 없음**)와 `06-blueprint-category.md`(UPROPERTY 카테고리)를 본다.

## 탐지 축
<위 표 그대로>

## 출력 형식
발견 하나당 아래 블록을 정확히 이 형식으로 낸다. 발견이 없으면 "발견 없음"만 낸다.

### [축ID] 한 줄 요약
- 위치: <파일 경로>:<줄 번호>
- 근거: 실제 코드를 3줄 이내로 인용한다. 인용 없는 발견은 내지 마라.
- 실패 시나리오: 어떤 입력/상태에서 무엇이 잘못되는지 구체적으로. "그럴 수 있다"는 금지. 재현 경로를 써라.
- 확신도: 높음 / 중간 / 낮음

## 금지
- 추측으로 발견을 만들지 마라. 코드를 읽지 않은 파일에 대해 쓰지 마라.
- 취향 문제(변수명 선호, 중괄호 스타일)는 보고하지 마라.
- 발견 개수를 채우려 하지 마라. 없으면 없다고 해라.
```

## 2단계 — 반박 에이전트 3개 (병렬)

탐색 3개가 모두 끝난 뒤, 다시 **한 응답 안에서 3번 호출**한다. 반박 에이전트 N은 탐색 에이전트 N의 발견만 받는다.

- `subagent_type`: `general-purpose`, `model`: `opus`
- 반박 에이전트에게는 **다른 탐색 결과를 주지 않는다.** 합의 여부가 반박에 영향을 주면 안 된다.

### 반박 에이전트 프롬프트 템플릿

```
너는 코드 리뷰 결과를 검증하는 반박자다. 아래 발견들은 다른 에이전트가 낸 것이다.

[읽기 전용] 파일을 절대 수정하지 마라.

너의 임무는 각 발견을 **무너뜨리는 것**이다. 동의하는 게 목적이 아니다.
각 발견에 대해 실제 코드를 직접 열어 다음을 확인해라.

1. 인용된 코드가 실제로 그 위치에 그대로 있는가.
2. 상위 호출자나 다른 곳에서 이미 방어(null 체크, 권한 체크, early return)하고 있지 않은가.
3. 주장된 실패 시나리오가 실제로 도달 가능한가. 도달 불가능한 경로는 아닌가.
4. 엔진이 이미 보장하는 것을 결함이라 부른 건 아닌가.
5. 이 코드가 "의도된 것"이라는 근거(주석, 규칙 파일, 인접 코드 패턴)가 있지 않은가.

## 검토할 발견
<탐색 에이전트 N의 출력 그대로>

## 출력 형식
발견 하나당:

### <원본 요약>
- 판정: 반박 실패 / 부분 반박 / 반박 성공
- 근거: 실제 코드 인용. 인용 없는 판정은 무효다.
- 부분 반박이면: 어느 전제가 성립하고 어느 전제가 안 되는지 나눠 써라.
- 반박 성공이면: 왜 문제가 아닌지 결정적 근거를 대라. "가능성이 낮다"는 반박이 아니다.

## 주의
- 반박하지 못했으면 솔직히 "반박 실패"라고 해라. 억지로 깎지 마라.
- 반대로 발견이 맞아 보인다고 그냥 넘기지 마라. 반드시 1~5를 다 확인하고 판정해라.
```

## 3단계 — 병합과 분류

메인 에이전트가 직접 한다. 이것까지 위임하지 않는다.

### 병합

같은 결함을 여러 탐색이 찾았으면 하나로 합치고 **합의 수(1/3, 2/3, 3/3)** 를 기록한다. 위치가 같아도 원인이 다르면 별개다.

### 분류

| 카테고리 | 조건 |
|---|---|
| **치명적** | 반박 실패 + 크래시 / 무한루프·행 / 세이브 손상 / 멀티플레이 상태 불일치. 즉시 고쳐야 한다. |
| **유효** | 반박 실패. 실제 결함이지만 영향이 국소적이거나 조건이 제한적. |
| **부분 유효** | 부분 반박. 전제 일부만 성립하거나 특정 조건에서만 발생. 성립하는 부분과 아닌 부분을 명시한다. |
| **경미** | 반박 실패지만 실행에 영향 없음. 스타일·관례·미세 성능·`TEXT`/`CONV` 다수가 여기. |
| **오탐** | 반박 성공. |

합의 수는 분류를 **바꾸지 않는다.** 근거로만 판단한다. 3/3 합의라도 반박에 무너지면 오탐이고, 1/3이라도 반박이 실패하면 치명적일 수 있다. 합의 수는 참고용으로 표기만 한다.

판정이 갈리거나 근거가 부족해 스스로 결론이 안 나면 **분류를 지어내지 말고** 그렇다고 적는다.

## 4단계 — 보고

기본은 **대화창에 마크다운으로 출력한다.** 파일로 남기라는 요청이 있을 때만 `Docs/Code_Review_<YYYY-MM-DD>.md`에 쓴다.

```markdown
# 코드 리뷰 — <범위>

대상: <파일 수>개 파일, <라인 수>줄 · 탐색 3 / 반박 3

| 카테고리 | 개수 |
|---|---|
| 치명적 | n |
| 유효 | n |
| 부분 유효 | n |
| 경미 | n |
| 오탐 | n |

## 치명적

### 1. [CRASH] <요약>
- 위치: `경로:줄`
- 합의: 2/3
- 무엇이: <결함>
- 언제: <실패 시나리오>
- 반박 시도: <반박 에이전트가 뭘 확인했고 왜 실패했는지>
- 제안: <고칠 방향. 코드 전문이 아니라 방향만>

## 유효
...
## 부분 유효
(성립하는 전제 / 성립하지 않는 전제를 나눠 쓴다)
...
## 경미
(한 줄씩. 위치 + 요약만)
...
## 오탐
(한 줄씩. 무엇을 왜 기각했는지. 다음 리뷰에서 같은 걸 또 파지 않기 위해 남긴다)
```

**오탐 절을 생략하지 않는다.** 무엇이 걸러졌는지가 이 리뷰의 신뢰도 근거다.

보고 후 수정 여부를 묻는다. **묻기 전에 고치지 않는다.**

## 안 하는 것

- 발견이 없으면 없다고 보고한다. 카테고리를 채우려고 경미 항목을 부풀리지 않는다.
- 리뷰 중 파일을 수정하지 않는다.
- 커밋·푸시하지 않는다.
- `.uasset`을 열지 않는다.
